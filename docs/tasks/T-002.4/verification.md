## Verification scenarios

### V-01 — Every affected overview retains the complete independent review route

Covers: AC-01, AC-02, C-01

Intent: Reject an overview or example that permits author self-acceptance,
omits discovery or stops at a verdict without the coordinator's obligations.

Given:

- Settled child contracts and the affected root README, profile guide, flow
  README, handoff/layout references, role tables and launch examples.
- A prepared executable package and a guided direct request requiring review.

When:

- Trace each affected functional-review route from submission to continuation.

Then:

- Applicable prior conditional stages lead to fresh discovery, then a separate
  independent acceptance call, then coordinator recording and authorized
  continuation. No optional wording permits discovery to be skipped.
- Production authors cannot accept their own bytes by loading another skill.
- Prepared packages retain verification and ready preflight inputs; direct
  requests retain guided inputs without requiring a high-assurance packet.
- Distinct discovery/decision reasoning recommendations remain human guidance;
  they add no launcher adapter, fifth metadata scalar or observed-runtime claim.

Oracle / boundary:

- Inspect complete routes and examples across affected source/profile surfaces,
  comparing their role boundaries with the child contracts. Text checks prove
  structural agreement, not actual independence or runtime reasoning settings.

Variants:

- Prepared package; guided direct request. Preserve applicable conditional-stage
  references without constructing T-003's full route matrix.

### V-02 — Guidance and report contracts preserve role ownership and uncertainty

Covers: AC-02, C-01

Intent: Reject consistent stage names that still transfer decision, gate or
tracker authority to the wrong role, or turn ordinary unknowns into routine stops.

Given:

- Source discovery/acceptance/preflight contracts, report references and composed
  guides, with child-supplied contextual disposition and uncertainty cases.

When:

- Trace required inputs, outputs, permitted writes and uncertainty routes across
  those contracts and their fixture expectations.

Then:

- Discovery consumes task/preflight context and current evidence, preserves
  complete or explicitly partial coverage, and owns justified workflow aggregate
  records, including correction; it grants no verdict, deferral or advancement.
- Acceptance admits current evidence and decides every finding without broad
  rediscovery or repeating discovery's aggregate. Green tests cannot waive an
  AC failure or confirmed material operating/business/contract/refactoring risk.
- Ordinary unknowns continue under a stated reasonable assumption. Required
  missing proof routes to its evidence owner. Only an unresolved serious-delay
  or costly-later-repair decision outside available authority needs a focused
  user question; resolvable authority is used first.
- Discovery/acceptance own only their authorized report outputs, using unused
  numbered paths in durable mode. They cannot repair production, overwrite
  history or write real known issues. Coordinator recording remains separate.

Oracle / boundary:

- Semantic contract inspection and comparison of supplied expected routes and
  write scopes. Prompt/write compliance by actual agents remains unrun here.

Variants:

- Ordinary contextual unknown; missing required evidence; exceptional unresolved
  consequence; exceptional concern resolved by supplied authority. Guided and
  durable report modes retain their existing permissions.

### V-03 — Canonical installation projects exact managed bytes and preserves users' bytes

Covers: AC-03, C-03

Intent: Reject existence-only projection proof or a rerun that changes unrelated
files, skills, helpers or AGENTS text.

Given:

- Current source profile and canonical `scripts/install_development_skills.py`.
- The existing disposable committed Git target fixture contains project files
  and AGENTS instructions. Retain before/after identities for unmanaged content.

When:

- Run the canonical installer into that target.
- Add unrelated target content and an unmanaged skill/helper, introduce stale
  managed content using the existing rerun fixture, then explicitly rerun.

Then:

- Both installations succeed and project discovery/acceptance packages and
  required references, the profile guide and every selected sibling helper.
- Managed relative file sets and bytes match the source projection, respecting
  existing installer exclusions; the expected marked AGENTS block appears once.
- Rerun restores the managed projection and removes stale managed content while
  preserving unrelated file/skill/helper bytes and AGENTS text outside the block.
- Selected skill sources, guide, helper manifest, focused tests and installation
  documentation agree; discovery selection is already present from T-002.1.

Oracle / boundary:

- Actual installer process results and filesystem byte comparisons for the
  committed disposable target, plus exact managed-block comparison and unmanaged
  before/after bytes. Inspect installer constants even if no change is needed.

Variants:

- Initial install; explicit rerun. No active installation refresh, unborn-target
  repair or new drift-check capability is required here.

### V-04 — Preflight-only exposure survives into discovery and decision inputs

Covers: AC-02, AC-04, C-01

Intent: Reject a handoff that retains paths but loses the only supplied material
context, or supplies a report without the implementation needed to verify it.

Given:

- Child-supplied authority, verification, preflight, current implementation/tests
  and relevant conditional evidence for a passing-AC fixture whose material
  operating exposure is stated only in preflight.
- Its existing bounded probe distinguishes risky behavior from the supplied
  mitigated control under that exposure.

When:

- Construct the local discovery and decision input sets from that setup and
  exercise the supplied disposable probe at its declared boundary.

Then:

- Discovery input preserves the exposure and connects it to the decisive probe;
  decision input retains the same context, current evidence and source identities.
- Probe observations distinguish the supplied harmful consequence from the
  control. Passing explicit ACs do not erase material-risk decision obligations.
- Every constructed report is labeled fixture data, with intended producer and
  consumer roles; none is described as an observed discovery/acceptance call.

Oracle / boundary:

- Inspect actual assembled consumer inputs and compare them with upstream
  context; observe the existing fixture's public operation and persisted effect.
  Expected report/disposition content is contract evidence, not agent behavior.

Variants:

- Preflight-only material exposure; supplied mitigated control.

### V-05 — Mixed conditions retain the blocker and each unfinished row's route

Covers: AC-02, AC-04, C-01

Intent: Reject fixture composition that drops missing proof after finding a
blocker, or uses a single verdict to hide separate correction/evidence owners.

Given:

- A supplied current implementation with a reproducible confirmed blocker,
  a different required blocked/unchecked row and its concrete capability reason.
- Fixture authority distinguishes authorized bounded correction from a case
  where authority, scope, permission or dependency prevents that route.

When:

- Exercise the supplied blocker probe and inspect composed discovery-to-decision
  inputs and explicitly constructed expected continuation records.

Then:

- Stable finding and coverage IDs, current proof, unfinished-row reasons and
  owners survive unchanged in identity through both input sets and continuation.
- Authorized bounded correction yields the expected CHANGES_REQUESTED route,
  retaining evidence recovery and any necessary authority question separately.
- When bounded correction cannot be admitted, the expected route is INCONCLUSIVE
  with the confirmed blocker retained. Missing decisive proof alone also routes
  INCONCLUSIVE to its evidence owner; ordinary uncertainty alone does not.
- Neither incomplete route permits advancement or marks unfinished rows clean.

Oracle / boundary:

- Actual local blocker signal plus field-by-field comparison of assembled inputs
  and expected fixture records against IF-005. Constructed verdicts are not
  observed acceptance outputs.

Variants:

- Correction authorized/prevented; blocked/unchecked required proof; mixed case
  with an unresolved decision-critical question; missing proof without a blocker.

### V-06 — Corrected fixtures carry current evidence and discovery-owned gates

Covers: AC-02, AC-04, C-02

Intent: Reject a corrected handoff that copies prior pass labels, discards an
unfinished row or assigns the clean-review aggregate to acceptance.

Given:

- Supplied failure, corrected implementation/tests and prior discovery/decision
  fixture records with stable findings, regressions and unfinished rows.
- Existing targeted probes and owning gate commands; no new gate is introduced.

When:

- Exercise the supplied failure and corrected targeted probes and inspect the
  ordered expected discovery/decision gate records for current fixture bytes.

Then:

- Failure remains observable; safe independent rows remain represented and an
  ordinary aggregate is suppressed after decisive failure with its reason.
- Corrected setup produces current clean targeted observations, reruns relevant
  regressions and resolves runnable unfinished rows without renaming IDs.
- Expected clean discovery reconciles authority/scope, preserves concrete reasons
  for any unavailable rows and owns one justified aggregate after targeted proof.
- Gate records retain command or not run, owner, stage, reason and current
  evidence. Acceptance consumes them without duplicated aggregate execution.
- An inherited late-omission case retains the premature-gate record, missing
  targeted proof and justified rerun/suppression ordering.

Oracle / boundary:

- Actual targeted fixture observations tied to failed/corrected bytes and ordered
  expected gate/consumer records. A constructed gate pass is never reported as an
  executed command. Actual multi-call correction compliance belongs to T-005.

Variants:

- Failure to clean correction; inherited late omitted row that passes/fails.
  This does not implement T-003's full correction route matrix.

### V-07 — Coordinator deferral examples remain usable by the next preflight

Covers: AC-02, AC-04, C-02

Intent: Reject loss of deferral provenance, acceptance writing the tracker, or
later consumers treating a prior deferral as blanket permission.

Given:

- A supplied accepted non-material deferral example with passing required proof
  and a separate, explicitly constructed coordinator-owned ART-008 record.
- Relevant unchanged-exposure, changed-exposure/consumer and unrelated later
  preflight inputs from predecessor fixtures.

When:

- Compose the decision-to-coordinator and record-to-preflight inputs, then
  exercise existing local consumer compatibility probes where supplied.

Then:

- Coordinator recording precedes authorized advancement; no reviewer acquires
  real tracker-writing or portfolio authority.
- The record preserves stable IDs, task/review/finding provenance, trigger,
  consequence/evidence, impact/likelihood, affected boundary/consumers, rationale,
  follow-up owner/action and reassessment conditions. Supplied optional context
  links retain their meaning without becoming mandatory metadata.
- Relevant preflight receives the record and reassesses compatibility/current
  exposure. Unchanged exposure retains the accepted disposition; changed exposure
  or required-consumer incompatibility retains an owned reassessment route.
- Unrelated inputs do not acquire a defect obligation from the record. A
  portfolio-priority change alone does not reopen task acceptance, and planned
  future work alone is not mitigation or permission to defer a current blocker.

Oracle / boundary:

- Compare actual assembled record/consumer inputs against ART-008 and IF-006;
  observe supplied local compatibility signals. Do not prescribe a new preflight
  verdict where the settled contract requires reassessment and routing only.

Variants:

- Relevant unchanged exposure; relevant changed exposure/required consumer;
  unrelated task; priority-only change contrasted with actual exposure change.

### V-08 — Composition preserves inherited decisive cases and runnable setup

Covers: AC-04

Intent: Reject a composition fixture that keeps summaries while deleting hard
cases, public entry points, starting state or cleanup needed for later proof.

Given:

- Predecessor discovery/acceptance/preflight eval definitions and setup files,
  including existing lifecycle, public, schema, process and continuation cases.

When:

- Compare the composed setup and consumer expectations with those predecessor
  cases and the child contracts, accounting for permitted role-specific changes.

Then:

- Every inherited material case retains authority, legitimate starting state,
  current implementation/tests, exact invocation, decisive signal and cleanup.
- Lifecycle repetition/resume/retry; missing capability; separate Git index and
  worktree identity; ledger cardinality/order/type cases; workflow tampering,
  replay and decision-boundary cases; valid/targeted-invalid validator probes;
  and resistant-descendant/pipe/race process cases remain available.
- Prior continuation retains every stable finding/row and current-proof
  obligation. Role changes do not erase cases or make discovery grant verdicts.
- Unavailable or unrun boundaries remain explicit gaps. Schema/syntax checks,
  mock-only evidence or setup success do not replace required real observations.

Oracle / boundary:

- Case-by-case preservation audit of supplied definitions, setup and consumer
  inputs. Reuse current predecessor runtime evidence where applicable; record
  gaps and route changed setup/probe capability to preflight. This scenario does
  not authorize repeating expensive process suites or actual role evals.

Variants:

- All inherited material cases, grouped by their existing invariant and boundary.

### V-09 — Results expose evidence limits and provide a reproducible T-005 handoff

Covers: AC-05

Intent: Reject local green checks or invented reports being presented as
installed-flow behavioral qualification.

Given:

- T-002.4's structural checks, semantic inspection, actual disposable installer/
  probe observations, fixture records and unrun separate-call requirements.

When:

- Inspect the new task-local result and qualification-setup handoff.

Then:

- Results distinguish structural tests, actual installer/probe behavior,
  semantic contract inspection and unrun agent compliance.
- Each claimed observation includes supplied inputs/setup, exact command and
  working directory, source identities, result/oracle and material gap. Fixture
  records are distinguished from raw observed outputs.
- T-005 receives reusable commands/setup, source/target identities where tested,
  intended producers/consumers and explicit unrun gaps for actual role calls.
- No installed-flow behavioral qualification or overall completion is claimed
  from local checks. Plans, historical reviews and active installation stay intact.

Oracle / boundary:

- Audit claims against actual local evidence and their reproducible inputs.
  A success label without an exercised boundary is insufficient evidence.

Variants:

- Executed local success/failure; constructed expected record; unavailable/unrun
  boundary, including separately authorized T-005 behavior proof.

  projection spot-check; no whole-repository, network or agent-budget gate is

  conflict to task design/preflight rather than weakening its oracle. Return
  semantic defects to the responsible child instead of redesigning them here.
