### V-01 — Preserve evidence levels and child dispositions

Covers: revised AC-01.
Intent: Reject a report that turns supplied history or local tests into composed
qualification, drops a parent requirement or upgrades a prior verdict.
Given: .1 acceptance, .2 results/acceptance and .3 results/discovery are available,
with their inventories, ledgers and explicit deferral gap.
When: compare the report's P-01–P-07 and six-child account with those sources.
Then: .1 setup ACCEPT, .2 INCONCLUSIVE, .3 partial discovery without leaf
acceptance, waived .4/.5 and .6's documentation-only submission stay distinct.
Local/runtime facts, actual leaf reviews, staged fixture history and reported
personal use have separate evidence meanings. Existing case IDs remain accessible
through source links; no new per-row grading is required.
Oracle / boundary: source-to-claim reading and resolving local document links.
Variants: all seven parent requirements and all six child dispositions.

### V-02 — Limit the assurance claim to the revised closure

Covers: revised AC-02.
Intent: Reject owner waivers labeled as passing qualification, or an old receipt
presented as proof of today's active installation.
Given: the owner ended the additional campaign and accepted personal-use risk.
When: read the report's closure, unrun-work and installation-limit statements.
Then: full behavioral qualification remains incomplete; existing ACCEPT,
INCONCLUSIVE and partial records are preserved. The report records unrun
preparation/contextual/deferral/correction boundaries, additional runtime gaps,
maintainability sensitivity and point-in-time installation limits. No new campaign
or maintainability benchmark becomes a completion requirement.
Oracle / boundary: direct agreement with the reassessment and cited reviews;
workflow identity alone cannot support an installation qualification claim.
Variants: historical evidence, owner-reported use, waived unrun evidence.

### V-03 — Preserve protected history and consistent submission state

Covers: revised AC-03.
Intent: Reject altered history, disagreement between the two outputs or automatic
advancement based on documentation completion.
Given: a clean entry worktree and unchanged dated proposal, source, installation,
plans, index and upstream evidence.
When: inspect both new documents, links, final changed paths and protected bytes.
Then: both outputs describe reduced personal-use closure and READY_FOR_REVIEW;
no self-issued acceptance, actual deferral, qualification pass or release appears.
Only new .6 preparation/results/evidence and the named ART-012 report are added.
Oracle / boundary: read both outputs; compare protected file identities with entry;
resolve links; run `git diff --check` and inspect all untracked paths separately.
Variants: none.

Implementation handoff: derive ready standalone guided preflight before report
implementation. Use source reading, local link/scope checks and diff checks only.
No owning code suite, archive replay, installation renewal, controlled-fault
harness, live/model eval or broader aggregate is required. Fresh discovery owns
corroboration, followed by a separate acceptance decision.
