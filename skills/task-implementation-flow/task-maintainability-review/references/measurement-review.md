# Independent measurement and evidence

This protocol governs the existing fresh maintainability review. Source presence
is not installation availability. Resolve the session's available skill first:
a matching project-local `.agents/skills/` copy takes precedence. Resolve its
runtime only from sibling `.agents/scripts/`; a source distribution uses
`scripts/` beside `skills/`. Never borrow another installation, provision tools
implicitly or refresh the active installation during a run.

## Establish actual comparison inputs

Consume original baseline B, implementer comparison I, affected-function
attribution, rationale and native-obligation handoff. Check logical project,
original inventory/source snapshots, governed folders, effective tools/settings,
selected checks, format/profile completeness and current submitted-byte identity.
Absolute root and matching relative paths alone do not establish project identity.
Matching Git status text does not establish matching bytes. The original capture
predates edits; do not require current edited hashes to equal B. Verify the
preserved before state and compare current hashes against I. Record stale I as
history and use actual submitted bytes for your own comparison R.

From diff and local context, select changed, added and deleted Python paths
inside original folder coverage, including relevant tests, evals, fixtures and
harnesses. Existing empty captured parents cover future files. Do not count
untouched siblings as affected merely because their file changed or lines moved.
Explain rename/move/extraction relationships and assess the original
responsibility with its helpers. Unmatched symbols and absent native counts stay
unknown, never numeric zero or invented cross-symbol deltas. Do not build an
attribution analyzer.

With an already prepared pinned interpreter, invoke the active installation's
launcher yourself:

```text
<python> <same-installation-scripts>/measure_maintainability.py compare <affected-paths> --root <repo> --baseline <original-B.json> --output <fresh-R.json>
```

Use fresh named paths for both JSON and text siblings. Preserve B, I, all prior
reports, unrelated user work, source and the real index. Record command, exact
pairs, scope, tool/settings identity, status and current source hashes. The
author's I alone never satisfies independent comparison. Snapshot authorized
write boundaries before/after; only new authorized reports may change.

In isolated review, name exact source and receiving paths for both siblings of
B and I and explicitly transfer them. Ignored reports do not travel in commits.
Validate project/applicability at the receiver; a different mount is permitted
provenance, not evidence of a different or matching project by itself.

## Recover without inventing history

Missing, stale, incomplete, incompatible or uncovered evidence cannot claim a
clean or complete comparison. Attempt recoverable current measurement at fresh
paths before declaring evidence absent. Without usable B use `measure`, label it
current-only and retain the before-state gap. Remeasure before code only from
verified exact preserved pre-edit bytes. Never capture edited code as original B,
replace history, tune settings/exclusions or infer missing values.

Record docs-only and unsupported-language scope as N/A with reason; preserve
native duties. Unavailable runtime/pins authorize no setup or cross-root fallback.
Advisory absence alone does not force `INCONCLUSIVE`: continue bounded semantic
review when possible. If explicit authority makes missing evidence indispensable,
name that authority, gap, owner and recovery; mandatory proof stays owed and an
unresolved material gap normally yields `INCONCLUSIVE`. These execution statuses
are separate from the semantic verdict and functional acceptance.

Scope expansion belongs to the task authority, not the read-only reviewer.
Require authorized scope resolution plus exact verified preserved pre-edit
supplemental evidence, retaining B/history. If exact before bytes are unavailable,
attempt current measurement and state the unrecoverable historical gap and its
owner. Authorization alone supplies no before state. Keep the owed route visible.

## Dispose of each required rationale

Use effective targets (provisionally complexity 10, statements 50, arguments 5).
Apply these rules to actually affected responsibilities:

| Condition | Disposition duty |
|---|---|
| Growth at or below target, including equality | Information only; no individual defense or metric-driven refactor. |
| New function exceeds target or existing function newly crosses it | Explicitly assess retained structure and useful local alternatives. |
| Existing breach worsens | Explicitly assess and justify the increase. |
| Materially edited hotspot remains above target, equal or improved | Consider useful bounded cleanup and explain retention; target compliance is not mandatory. |
| Hotspot reaches target or stays untouched | No retained-breach rationale; untouched debt is context only. |
| Metrics fall but ownership/names/navigation worsen | Assess semantic cost with helpers; numbers do not excuse regression. |

Each required obligation identifies report, function, metric, known before/after,
why the decisions belong together and a plausible alternative's cost. Recover
missing explanations through the implementer; leave the obligation/gap visible
until resolved. One cohesive explanation can cover related metrics, but every
obligation must have an identifiable disposition. Record agreement or a concrete
counterargument, credible future maintenance cost and smallest reasonable
correction. A threshold alone cannot cause `CHANGES_REQUESTED`. Preserve naming,
locality, test-asset and abstraction-cost review from the main protocol. Do not
split cohesive code, hide arguments or add speculative layers to satisfy metrics.

## Retain native policy beside advisory evidence

For each existing native obligation retain exact command, governed scope,
policy/requiredness, existing owner/stage, checked-byte identities, result and
producer/stage. Discover through a registry or equivalent documented commands;
require no registry and record none when no commands exist. Preserve whole-project
scope even when R measures only changed files. Conflicting policy returns to its
authority owner; never infer an exception from a tool name or metric exit code.

Validate current saved evidence. Reuse aggregate constituents only when exact
commands, coverage, policy, whole scope and current bytes are established; do not
rerun them merely for report sections. Respect stricter reviewer-run architecture
authority. Missing/stale proof returns to its owner or an authorized focused run;
record new current evidence and retain the historical failure/pass. Unavailable
required gates without valid evidence/exception remain incomplete, normally
`INCONCLUSIVE`. Required native failures stay visible even beside successful or
N/A metrics. New/worsened hard architecture violations have their existing
`CHANGES_REQUESTED` consequence; functional investigation stays with its owner.
This review does not duplicate general functional review.

Optional run-evidence availability is separate. A wrapper may capture one real
comparison; never execute a second comparison solely for instrumentation. Missing
instrumentation neither supplies missing metrics/native proof nor creates a duty.

## Complete reports and corrections

Extend the existing next numbered package report with all comparison references,
status/coverage/byte identities, every required rationale disposition, current
native evidence and owed proof/owners. Required dispositions, gaps and confirmed
blockers are uncapped; only optional WARNINGS have a maximum of three. Continue
bounded coverage after an early decisive blocker. A genuine permission/capability/
budget stop retains reached dispositions, every outstanding row, concrete reason
and separate correction/evidence/decision owners; incomplete cannot mean ACCEPT.

Keep B and every historical pair through corrections. Fresh I2/R2 compare edit
two to B, never to I1/R1. Changed bytes stale affected verdicts, rationale and
native proof; demonstrably unchanged scope may retain applicable evidence. Keep
surviving/resolved finding IDs, never recycle them, and reconcile the whole ledger.

After an accepted review, name the first outstanding stage and complete ordered
remainder: applicable registry synchronization, fresh discovery, separate
acceptance. Omit only stages absent or already current for submitted scope/bytes;
do not invent stages. Corrections re-enter only conditional duties whose scope
they affect, including significant test/eval/harness changes. An explicit trivial
exception applies only to its authorized scope. Measurement warnings add no
review stage. Name owners without executing, delegating or waiting for them.
Downstream consumers preserve gaps/blockers and return them to the owning stage;
a prior ACCEPT label cannot clear stale/incomplete proof.
