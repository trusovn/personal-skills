## First bounded pass: existing runtime, local evidence only

Use at most 15 tool calls or 40 minutes, with one result report beside this file.
Stop earlier when the decisive capability cannot be established. This is a
proof-only investigation, not an executable implementation package or a new plan.

1. Record the resolved binary/version, effective launch configuration and Git
   baseline. Read local interface evidence first with the available installed
   `openai-docs` workflow. Consult official sources only if local evidence leaves
   a control unresolved. Do not invent flag combinations from names alone.
2. Identify a supported way to exclude direct and deferred delegation while
   retaining local shell and native patch. Do not change the runtime, installation
   or production code. If the installed runtime has no viable supported control,
   publish that result and stop runtime qualification. Supply a concrete candidate
   build/control and its provenance, if known, for a separate owner decision.
3. For a viable existing-runtime control, prepare the smallest task-local probe
   delta and focused verification before execution. Inspect existing probes and
   coverage under project-local `testing-discipline`; reuse the inventory and
   permission fixtures. Do not edit the submitted probes merely to make them pass.
   Recheck preparation for changed scenarios or permission scope in a new supplement.
4. Test the control with the real CLI/router and a non-billable local service.
   Observe request `additional_tools` and the executed nested inventory on initial
   and follow-up requests for both effective actor profiles. Require observable
   shell execution and native-patch behavior, not tool names alone. Exposed
   delegation, an empty/unobserved inventory or lost required execution is failure.
   Do not invoke delegation. Retain complete local captures and cleanup evidence.

Local investigation is authorized. Any enclosing-sandbox rejection must use the
normal command escalation path. Do not start live actor/model sessions, refresh

- **Now:** preserve the staged seven-file submission; perform only the bounded
  local investigation above. Do not alter official plans or accepted reports.
- **Runtime change:** if needed, present the exact candidate version/build,
  source, isolated evaluation method, permission impact and cleanup plan. Obtain
  explicit owner approval before replacement/change. No alternative backend or
  weaker safeguard is an acceptable way to clear F-01.
- **Live qualification:** all five prior sessions are consumed. Before any new
  billable run, present the exact session count, settings, roles, prompts/probes,
  retained artifacts, budget and stop conditions. Batch compatible model, role,
  native-patch and parity checks where the evidence permits. Do not claim a fixed
  minimal count until the controls and capture method are concrete.
- **Independent review:** both earlier authorized review sessions are consumed.
  Obtain explicit authority for fresh independent discovery and then a separate
  fresh acceptance session. Neither this proposal nor a local producer pass
  renews that authority. Use the project-local installed skills; no installation
  refresh or source substitution. Preserve separate evidence and decision owners.

Fresh discovery must receive the recovered captures, current preparation,
runtime/configuration identities, all seven stable rows above and the prior
reports. It must corroborate the model/filesystem evidence and attempted native
denials, rather than copying summaries as independent proof. Only after targeted

decides **T-002 readiness explicitly**, preserving unchanged downstream lifecycle,

is authorized by this proposal, even if capability recovery succeeds.
